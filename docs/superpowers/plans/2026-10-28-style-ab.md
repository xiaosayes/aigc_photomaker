# 四风格 A+B 优化 Implementation Plan

> **后续路线替换**：用户已明确要求不再维护旧实验开关，默认工作流直接替换为官方 SDXL Base 1.0 + InstantID。本文旧任务清单用于追溯，不用于回滚当前实现。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用强化提示词、四个锁定 SDXL 风格 LoRA 和输出单人脸守卫提升风格辨识度并阻止多人结果交付。

**Architecture:** `StylePreset` 提供每风格 LoRA 文件和强度，`prepare_workflow` 将风格 LoRA 串联到身份 LoRA 后；Turbo 再串 LCM。ComfyUI 自定义输出守卫在 SaveImage 前验证人脸数量，错误经现有 AppError 映射回 API。

**Tech Stack:** Python 3.11、ComfyUI API graph、PhotoMaker Plus、InsightFace、SDXL LoRA、pytest、JSON 模型锁。

## Global Constraints

- 保持 RealVisXL V5、完整 PhotoMaker V2、1024×1024、物理 GPU 1 和单活跃任务。
- 本地仅静态检查；pytest、模型下载和真实出图在服务器执行。
- 新模型必须固定 revision、大小、SHA256；初始强度为 cyberpunk 1.0、anime 2.0、ink_wash 0.8、oil_painting 2.0。
- 不自动重试输出人脸失败，不删除输入或输出人脸检查，不宣称未经实测的质量/性能通过。
